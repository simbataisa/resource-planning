# Assumption row explanations: draft for review

**Status:** Draft — awaiting QE practice lead approval

**Approved by / date:**

## Purpose

The MCP server's `describe_assumptions` tool (design spec
`docs/superpowers/specs/2026-11-13-mcp-server-design.md`, section 6.4) serves one short
explanation for each of the 142 assumption rows, so an AI assistant and a Quality Engineer can
understand what each value means. Today the message files hold labels only. This sheet is the
English draft for the QE practice lead to approve, change or reject, row by row.

## How the texts will be used

- Each approved text becomes the message key in the first column, under
  `assumptionsTab.help` in `apps/web/messages/en.json` (the row path with dots replaced by
  underscores).
- English is approved first. The Vietnamese text is then drafted under the same keys and goes
  through the review kit (`pnpm i18n:review` / `pnpm i18n:apply`, see `docs/i18n/README.md`).
- Until a row is approved, `describe_assumptions` returns its label only.
- The editor does not show these texts yet (out of scope).

## How to read this sheet

- **Explanation:** at most 280 characters: what the value means, its unit, and what raising it
  does to the result. Values marked "share" are fractions stored as 0–1 and shown as % in the
  editor (0.3 = 30%). Values marked "%" are already 0–100.
- **Source:** where the wording comes from, as a section name and line number. `HTML <section>
Lnnn` is a line of the prototype, `../SIT_Sizing_Model.html`; sections marked "(script)" are
  strings in its embedded script (field tips, derived drivers, calendar check, evidence effects).
  `JS META Lnnn` is a row label in `../sit-sizing-reference/prototype-engine-and-ui.js` (`META`,
  lines 84–211). "design 6.5" is the solution design `../SIT_Sizing_Model_Solution_Design.md`,
  section 6.5. Labels in the second column come from `apps/web/messages/en.json`. "needs author"
  means the sources do not say what the row means; the explanation is left empty and the reviewer
  is asked to write it.
- **Field types:** the 21 `ftypes_*` rows share one template, with only the field type changed.
  The sources give the range of cases (3–18 per field and layer, about 12 for a typical mix), not
  what each type's cases are.
- Rows appear in the order of `apps/mcp/src/generated/assumption-rows.json`.
