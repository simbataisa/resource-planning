# Engine findings log

Record anything noticed while porting or changing the engine: prototype quirks, rounding behaviour, suspected bugs, or a difference from the golden example.

**Never fix silently.** If a number would change, write an ADR and get approval first (AGENTS.md rule 3). Each item below is preserved exactly in engine 1.0.0 and is proven by golden parity and the bit-identical parity check (`pnpm --filter @sit/engine parity`).

Status: **Review** = for the tech lead and QE practice lead to decide, ideally with actuals (Release 3). **Keep** = intended behaviour, documented.

**Decision (2026-11-12, product owner):** all 13 behaviours stay as they are for Release 1. The five **Review** items are revisited with actuals in Release 3; any change goes through an ADR and a new engine minor version.

## Port notes

- `compute()` was split into the modules listed in design 6.3. Arithmetic order is unchanged, which is why results are bit-identical, not just within tolerance.
- Prototype names were kept where they appear in saved profiles (assumption keys, `explain` fields), so exported profiles import without mapping.
- The engine returns keys and numbers only. Labels for groups, sensitivity items (`SENSITIVITY_ITEMS[].key`) and derived-row formulas belong in the web app's message files (step 1.5/1.6).
