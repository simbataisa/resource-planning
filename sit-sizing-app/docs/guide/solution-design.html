SIT Sizing, feature by feature

SIT Sizing turns the single-file HTML prototype into a multi-user web app that estimates QE test cases, hours and FTE for SIT, data platform, AI product and performance testing. This page walks through the detailed design of each feature and links every one to the architecture decision records (ADRs) behind it.

Big picture · design 4

Architecture

Three app deployables built from one monorepo, plus Keycloak off the shelf. They share nothing at runtime but OpenID Connect and the REST API. The engine runs in the browser for live results and again on the server, whose numbers are authoritative.

ADR-0001 stack ADR-0002 Keycloak ADR-0016 MCP

Solid arrows: requests. Dashed: OIDC sign-in. Red: the MCP server calling the same REST API, as the signed-in user. Moving dots trace three request paths: browser → web → app DB (red), agent → MCP → web → app DB (gold), worker → mail (navy).

Request pathThin handler, one service

  1. app/api/v1/**/route.ts wraps in api(): user, rate limit, request ID, error mapping.
  2. server/services/*: access check, Prisma transaction, audit, DTO mapping.
  3. server/domain/*: pure rules (lock, review, compare, portfolio, variance) tested without a DB.
  4. packages/db: Prisma client, imported only via server/db.ts.

Schema firstOne contract

Zod 4 schemas in packages/schemas validate route input, parse client responses and generate the OpenAPI 3.2 document. A change flows schema → service → route → operations.ts → pnpm openapi:generate.

ClientHooks over a typed client

Pages under app/[locale]/(app)/. TanStack Query hooks in lib/query/ call typed functions in lib/api/ on the one Axios instance in lib/http.ts. Components never fetch directly.

Big picture · design 6 · R1

Calculation engine

@sit/engine is a pure TypeScript port of the prototype's maths: no I/O, no dates, no UI text. It imports only zod and @sit/schemas. The prototype's numbers are locked in as golden files, and the stored payload of every version carries the engine and schema version that produced it.

ADR-0013 engine version, upgrade on read ADR-0019 engine 1.1.0 ADR-0020 engine 1.2.0 ADR-0021 engine 1.3.0

ParityThe numbers cannot drift

  • 36 golden files in packages/engine/golden/: every group's cases exact, hours to 0.01, both modes.
  • Property tests: never negative; more scope never lowers cases; all gates met never raises FTE.
  • pnpm --filter @sit/engine parity: 5,000 random cases against the prototype source.
  • Stryker mutation score ≥ 70%; coverage 95%.

Change policyFlag, don't recompute

  • Stored results never change silently.
  • Older engine → "Computed with engine x.y" and "recompute as new draft".
  • Every read goes through upgradeStored(); rows are never rewritten.
  • Newer schema after a rollback → 409 NEWER_SCHEMA.

Access · design 10 · R1

Sign-in and roles

Who you are comes from Keycloak; what you may do in a project is stored in the app. The web app never sees a password.

ADR-0002 Keycloak ADR-0004 openid-client ADR-0014 admin role

Sign-in flow

GET pageno session→ 302 to KeycloakPKCE S256, state, nonce→ Sign inpassword (+ TOTP) or SSO→ /api/auth/callbackcode exchange→ Encrypted cookieJWE A256GCM, 8 h idle / 12 h max→ Upsert User by subgroup → Admin

The proxy refreshes every 10 minutes. Back-channel logout puts the Keycloak session id in RevokedSession, so sign-out elsewhere ends the app session on the next request.

  • One permission matrix, lib/rbac.ts (27 actions). Services enforce it; the UI only hides.
  • Cross-project access returns 404, not 403.
  • Admin = Keycloak group sit-sizing-admins, re-read at every sign-in; read-only in the app.
  • Realm baseline (password policy, lockout, token lifetimes, disabled flows) tested by pnpm test:idp.

Review and reuse · design 5.2, 10.5 · R1 R2 R3

Versions, approval, compare and restore

Saved versions are immutable. A QE Lead signs off one version as the figure the team commits to, with segregation of duties.

ADR-0007 approval and compare ADR-0013 recompute as new draft

States

DRAFTone per estimate→ SAVEDimmutable→ SUBMITTEDone at a time→ APPROVEDby a QE Lead→ SUPERSEDEDwhen a newer one is approved

Return sends a submitted version back to SAVED with a note. Restore and "recompute as new draft" both start a draft from an old version.

Segregation of duties

The author or submitter of a version cannot approve it, Admins included (403 SEGREGATION_OF_DUTIES). Pure rule in server/domain/review.ts; the UI disables Approve and says why.

One transaction per step

Guarded updateMany (409 RACE on a race), ReviewComment for the note, audit estimate.version.{submit,approve,return}, notification outbox rows.

Compare

GET /estimates/:id/compare?a=&b=: both summaries, per-group cases and hours, changed input and assumption paths (capped at 500). Uses stored results; never recomputes.

Assumption profiles and calibration

Named sets of assumption values, global (Admin) or per project (QE Lead), so teams start from measured values instead of uncalibrated defaults.

DRAFTeditable · clone with basedOnId→ PUBLISHEDnever changes→ RETIREDstops new use

Calibration

  • A row is calibrated when it differs from the engine default (custom-size rows: when it has a note).
  • Source and measured date per calibrated row; unknown paths refused (422).

Using a profile

  • New estimate: choose a published profile; default is the oldest published global one.
  • Open draft: POST …/draft/profile copies values, recomputes, records profileId (lock and rowVersion required).
  • Copy, don't link. The last published global profile cannot be retired (409 LAST_GLOBAL).

Calibrate and report · design 7 · R3

Actuals and variance

After an SIT cycle the team records what it measured against the approved version. Variance is computed, never stored. People, not the tool, calibrate the profile.

ADR-0011 actuals

What is recorded

Required: cases executed and total SIT hours. Optional: execution hours, cases designed and design hours, retested cases, productive hours per day, split by group. One record per cycle name and version. Only APPROVED or SUPERSEDED versions (409 NOT_APPROVED).

Rates inform the assumptions

Execution minutes per case → minutes; design minutes → designFSD; retest rate → retest; productive hours → hoursPerDay. Variance = actual − stored detailed estimate (server/domain/variance.ts).

Integration · design 9 · R1

API contract and error codes

REST under /api/v1, JSON only, every operation registered in a generated OpenAPI 3.2 document and browsable in a self-hosted Scalar reference behind sign-in.

ADR-0003 OpenAPI and Scalar ADR-0018 extensible error codes

Contract gates

  • No third-party generator: z.toJSONSchema plus server/openapi/build.ts.
  • Contract test: registry equals the route files; every $ref resolves.
  • Redocly lint; oasdiff breaking-change diff against main (OPENAPI_BREAKING_APPROVED to pass).

Error envelope

{ error: { code, message, details?, requestId? } }. code is a string with x-extensible-enum, so a new code is additive; clients fall back to status and message.

Draft writes

Every autosave, apply, renew and release sends X-Lock-Token and the draft's rowVersion. Rate limit 300 requests per user per minute by default.

Integration · design 9.5, 10.8 · post-R3

AI assistant (MCP server)

A QE talks to an AI coding agent, which proposes inputs and a profile from a BRD or FSD, explains every value, previews the result and, after an explicit yes, saves a version. The engine computes; the assistant never invents figures.

ADR-0016 MCP server ADR-0018 error codes
Coding agentClaude Code · Codex→ Keycloak sign-inpublic client or restricted DCR→ apps/mcptoken: aud sit-sizing-api, sid→ /api/v1same RBAC, lock, rate limit→ Auditchannel mcp

Read (8)

whoami, list_projects, list_estimates, get_estimate, get_version, compare_versions, list_profiles, get_profile

Understand (3)

describe_inputs, describe_assumptions (glossary with only QE-approved help texts), preview_estimate

Write (6), each behind an explicit yes

create_estimate, start_draft, update_draft, apply_profile, save_version, submit_version. Never approve or return.

Realm changes

  • Public client sit-sizing-mcp, PKCE S256, loopback redirects.
  • Anonymous dynamic registration under STRICT policies: public, PKCE, loopback, no mappers.
  • Default audience scope; tokens without sid or from built-in clients refused.
  • No offline tokens.

Lock safety

Write tools take the lock with takeover: false. If the editor holds it, the tool answers EDITOR_OPEN and writes nothing; the lock token means it can never end the editor's lock.

Clients

Supported: Claude Code, Codex. Antigravity: unsupported (never starts sign-in). Kiro: untested. Quickstart: assistant-quickstart.md.

0004Sign-in with openid-client and an encrypted session cookieAccepted2026-11-12

Decision

  • openid-client v6 (OpenID Certified) instead of the Auth.js v5 beta: code flow with PKCE S256, state, nonce, refresh, RP-initiated logout.

Consequences

  • Auth code lives only in server/auth and app/api/auth; every change needs named security review.
