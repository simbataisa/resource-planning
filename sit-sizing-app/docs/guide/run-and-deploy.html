Run and deploy

Follow the steps in order. Every command runs from the sit-sizing-app/ folder. The diagram shows what you will have running locally at the end of step 4.

Part 1

Run locally

Six steps. Use the list or the Next button; arrow keys also move between steps.

Install the tools

You need three things on your machine. Install them once.

Tool Version How to check
Node.js 24 node -v (with nvm: nvm use reads .nvmrc)
Container runtime Docker Desktop, or Rancher Desktop with dockerd (moby) docker compose version shows v2
Git Any recent git --version

Behind a corporate proxy that inspects TLS? Container builds need the organisation's root certificate. On macOS, step 4 exports it for you. Elsewhere, put the PEM file in docker/certs/ (see docker/certs/README.txt).

Get the code

Clone the repository and move into the app folder. Every later command runs from here.

terminal 
$ git clone <repository-url> TCB
$ cd TCB/sit-sizing-app
$ corepack enable   # provides pnpm 10.34.9, pinned in package.json

Install packages

This downloads the dependencies and generates the database client. The optional check confirms your machine is set up correctly before you start containers.

sit-sizing-app 
$ pnpm install
$ pnpm check   # optional: type check, lint, format, unit tests

If binaries.prisma.sh is blocked on your network, set PRISMA_ENGINES_MIRROR to the internal mirror before installing.

Start the stack

One command does it all. The first run builds images and takes a few minutes; later runs take seconds.

$ pnpm dev:up

The command waits until every service reports healthy. Check it yourself with curl -s localhost:3000/api/v1/ready; it answers "status":"ready".

Stop or reset

Stopping keeps your data. Resetting deletes the local database and starts fresh next time.

sit-sizing-app 
$ pnpm dev:logs    # follow the web logs
$ pnpm dev:down    # stop, keep data
$ pnpm dev:reset   # stop and DELETE local volumes
Variant Command Use it when
Production-like image pnpm stack:up You want to see the app exactly as it ships (read-only, non-root)
With tracing pnpm dev:obs You need request traces; Jaeger opens on :16686
Next.js on the host pnpm dev You want the fastest reload; needs the db container running

Part 2

Test before you merge

Run the whole suite on the exact code you are about to merge. A few green test files are not a green suite.

sit-sizing-app 
$ pnpm check           # types, lint, format, unit, golden
$ pnpm test:coverage   # coverage gates per layer
$ pnpm test:int        # API integration (Docker)
$ pnpm test:e2e        # production image + Playwright
# when packages/engine changed:
$ pnpm --filter @sit/engine parity

What each gate protects

check Code compiles, follows the rules, and the numbers match the prototype
coverage Engine 95%, schemas 90%, feature components 80%
int Every API route against a real PostgreSQL, plus migration drift
e2e Real sign-in and user journeys in its own stack (ports 23000 and 28080), so it can run next to dev:up

Release steps

  1. Jenkins on main is green and has published sit-sizing-web:<APP_VERSION>.
  2. Fill in docs/release-checklist.md in the release pull request.
  3. Back up the app and keycloak databases.
  4. Run the migration job (tools image) and wait for success. Migrations never run at app start.
  5. Roll out web and worker to dev, then sit, then prod after a human approval.
  6. Check /api/v1/health and /api/v1/ready, then sign in once.

Rollback

Redeploy the previous image tag for web and worker. Migrations are expand-only within a release, so the old version runs on the new schema.

Never edit or roll back a merged migration. Fix forward with a new one.

Environment variables outside local

All values come from the platform secret store. The app checks them at start-up and refuses to start if a rule is broken.

Variable Value
APP_ENV dev, sit or prod
APP_VERSION The image tag
DATABASE_URL postgresql://…/app
APP_BASE_URL Public URL; must be https://
AUTH_MODE oidc (dev sign-in is refused outside local)
OIDC_ISSUER https://<idp>/realms/qe-tools
OIDC_CLIENT_SECRET 16+ characters
SESSION_SECRET 32+ random characters
LOG_LEVEL info; debug and trace are refused in prod
SMTP_URL (worker) The approved mail relay; unset keeps emails queued

Still open: the hosting platform, the secret store and the Keycloak import job are being agreed with the platform team. The pipeline publishes only the web image today; build the tools image from the same commit for migrations and the worker.

When something goes wrong

Troubleshooting

"required variable … is missing"
Run pnpm dev:env to create .env. Never commit it.
Port 3000 or 5432 is already in use
Set WEB_PORT or DB_PORT in .env, then run pnpm dev:up again.
/api/v1/ready says the identity provider is not ok
Keycloak takes about 30 seconds to start. Wait, then retry. If it persists, check OIDC_INTERNAL_URL.
Keycloak says "Invalid redirect uri"
APP_BASE_URL must match the URL in your browser exactly, including the port.
Changed passwords in .env and now sign-in fails
The database init script runs only on an empty volume. Run pnpm dev:reset, then pnpm dev:up.
Hot reload misses changes on Rancher Desktop
Add WATCHPACK_POLLING: "true" under web.environment in compose.dev.yaml locally. Do not commit it.
Integration tests cannot reach Docker on Rancher Desktop
pnpm test:int finds ~/.rd/docker.sock by itself. For other tools, see runbook section 3.
"ERR_PNPM_… minimumReleaseAge"
The version you asked for is less than 14 days old. Pick an older version; do not lower the setting.
